# TavernGym engine architecture

TavernGym is a headless simulator of Hearthstone Battlegrounds solo mode (client 36.6.3.253932,
server rules 36.6.3) built as a reinforcement-learning environment. All game logic lives in the
pure-Rust crate `crates/taverngym`. `crates/taverngym-py` is a thin PyO3 layer exposed as
`taverngym._core`, and `python/taverngym` wraps it in numpy-based environments.

## Layers

```
content pack + tools/overlays/36.6.3.json ──tools/gen_carddb.py──▶ crates/taverngym/data/cards.json
                                                                        │ (embedded)
cards.rs   CardDb: card definitions, pool flags, golden links           ▼
engine.rs  Game + Ctx   ◀── recruit.rs / combat.rs / flow.rs
script.rs  hook table   ◀── content/*.rs (one Script per card)
actions.rs / obs.rs / env.rs / batch.rs / bot.rs ──▶ taverngym-py ──▶ python/taverngym
```

| Module | Responsibility |
| --- | --- |
| `cards` | `CardDb`: kind, tier, stats, types, keywords, golden/normal links, pool flags, Dark Gift windows; `cardid!` |
| `config` | `RulesConfig`: every rule value that is not a published server value, documented per field |
| `state` | `Minion`, `Item` (hand, Tavern and Discover entries), `HandCard`, `ShopSlot`, `Player`, `PlayerStats`, `Pool`, `Pending` |
| `engine` | `Game` and the effect context `Ctx` (summon, buff, damage, deaths, events, hand, Gold, Discover) |
| `recruit`, `combat`, `flow` | Tavern, prices and player actions; automatic combat; lobby setup, turns, pairing, elimination |
| `event`, `script`, `content` | `Event` and its `event::ev` masks; the `Script` hook table; the implemented cards (`docs/CONTENT.md`) |
| `actions`, `obs` | Flat action space with an exact legal mask; player-view observation encoding |
| `env`, `batch`, `bot` | `SoloEnv`, `BatchEnv`, heuristic bots |
| `experimental`, `debug`, `invariants` | Opt-in rules and their extra actions; JSON views and debug commands; state checks |
| `rng`, `types`, `guard`, `workers` | Seeded PRNG; shared value types; stack guard; worker threads |

## Card data and game state

`crates/taverngym/data/cards.json` is generated by `tools/gen_carddb.py` from a content pack
compiled from the client data (not distributed), with `tools/overlays/36.6.3.json` applied on
top; never edit it by hand. It is embedded at compile time and loaded once into the static
`CardDb` (`cards::db()`). A `CardId` is a dense index into it, `CardDb::fingerprint` identifies
the table, and golden and normal forms are linked (`golden_of`, `normal_of`). With
`ContentMode::Implemented` (the default `RulesConfig::content`) pools offer only cards with a
script or a keywords-only text (`script::implemented`); `ContentMode::AllVanilla` offers every
current-pool card and treats unscripted text as a vanilla body.

`Game` holds the config, seed, `Rng`, turn, `Phase`, players, the shared `Pool`, the lobby (types,
Deity, Dark Paradox form, and the minion, spell, trinket, gift and hero universes), pairings,
eliminations and combat records. It is plain data: `Clone` gives an independent copy and serde an
exact save. Minions and cards carry integer `EntityId`s from `Game::alloc_eid`. A `Player` holds
hero and Hero Powers, Health, Armor, Tavern Tier, Gold, warband (`board`), `hand`, Tavern
(`shop`), trinkets, Quests, Rewards, Secrets, persistent `effects`, `PlayerStats` counters and a
stack of `Pending` choices (hero, Discover, Choose One, target, Hero Power, trinket offer, Quest,
Timewarp); the top choice blocks every other action. Cards that do not fit a full hand wait in
`Player::hand_queue` until there is room (`Game::flush_hand_queue`).

## The effect context

`Ctx` owns two arena boards, sides 0 and 1. In the recruit phase `Game::with_recruit` moves the
acting player's warband into side 0 and back afterwards (side 1 only holds a Tavern minion during
a recruit-phase attack, `Ctx::tavern_attack`). In combat both warbands are cloned into sides 0
and 1, so a fight never changes the persistent warband by itself. Scripts act only through `Ctx`
primitives (`summon`, `buff`, `buff_perm`, `buff_temp`, `give_kw`, `damage`, `destroy`,
`resolve_deaths`, `add_to_hand`, `cast_spell`, `offer_discover`, `when_space`, `emit`, ...), so
a Deathrattle, summon or buff runs the same code in the Tavern and in combat. Across phases:

- Permanent gains in combat go through `buff_perm` / `give_kw_perm`, which also update the
  persistent warband copy. Hand, Gold and counters live on `Player` and persist.
- Player-level "this game, wherever they are" bonuses are `PlayerStats` counters.
  `Ctx::bump_player_stat` changes one and re-syncs every instance it reaches (board, hand,
  combat copies, the player's Tavern) through `apply_bonuses_to`, which is idempotent because
  each minion records the bonus it already carries (`pbonus_atk`, `pbonus_hp`).

## Scripts

A `Script` (`script.rs`) is a table of optional hooks: minion hooks (`battlecry`, `deathrattle`,
`start_of_combat`, `hand_start_of_combat`, `rally`, `avenge`, `after_attack`, `on_sell`,
`start_of_turn`, `end_of_turn`, `activate`, ...), event listeners (`on_event` with a `listens`
mask, `listens_in_hand`, `persistent_event`), `on_attach` (Magnetic cards, Dark Gifts, trinket
purchase, hero selection), spell and Hero Power hooks (`spell`, `hero_power`, `scheduled`,
`discover_pick`, ...), static `flags` (`script::flag`) and `innate` keywords. The display-only
`shown` hook returns the current numbers of the card text for the debug view and never changes
state; `tests/shown.rs` checks that a fresh instance shows the printed numbers.

A hook receives a `Me` (side, entity, card, golden, Choose One mode, position, data). Content
modules return `(card id, Script)` pairs from `scripts()`, collected by `content::all_scripts`.
The registry (`script::registry`) rejects duplicates and maps golden forms to their normal
form's script: hooks read `me.golden` and apply the golden numbers of the card text, never blind
doubling. Target specs of cards whose text does not say "friendly" also reach Tavern minions
(`TargetSpec::widened`). Magnetized cards and Dark Gifts are attached to their host
(`Minion::attached`), and their hooks run with the host as `me.eid`.

## Events

`Ctx::emit` serves the event's own side first, then the other. Within a side: persistent player
effects (once per stack), Hero Powers, trinkets, Quest Rewards, Secrets, Quests, then board
minions left to right (host before its attached cards), then cards listening from the hand. This
cross-source order is a simulator convention (the server's full order is not published). A cast
and a minion play are announced twice: "whenever" listeners hear the first announcement, all
others the second (`content::acts_whenever`). The damage events of one attack exchange are held
back until both sides have dealt damage. Nesting deeper than `RulesConfig::max_effect_depth`
(64) is cut off and marks the context truncated.

## Death resolution

`Ctx::resolve_deaths` repeats until the boards are stable (at most 64 rounds). Each round,
first attacker's side first:

1. remove every dead minion and record a `DeadRecord` (card, final and peak stats, position);
2. emit `Died`, and `Killed` when the killer is on the other side (`Killed.side` = killer's side);
3. outside combat, return the dead minions' pool copies;
4. run Deathrattles at each death position, `Ctx::deathrattle_mult` times;
5. resolve Reborn right of those summons (a fresh card with 1 Health);
6. tick Avenge once per death on the minions present at that death;
7. in combat, check Deity awakening.

A "when you have space" summon (`Ctx::when_space`, `SpaceReq`) asked for meanwhile waits until
the outermost resolution settles; Tavern triples also wait for the batch. Divine Shield can
absorb several hits (`shield_hits` / `shield_max`); Venomous is used up by the first hit that
deals damage (Cleave carries it to every target of that attack).

## Game loop

`Game::new(seed, cfg)` draws the lobby: `lobby_races` (5) of the 10 types (`lobby_types` and
`aberration_forced` can force some), a Deity (C'Thun or Y'Shaarj, only in Aberration lobbies),
one Dark Paradox form (no Tier 5 form with Undead, no Tier 5 or 6 form with Y'Shaarj), the
universes, the shared pool and `hero_choices` offers per seat. Phases run
`HeroSelect → Recruit ⇄ combat round → GameOver`; recruit turns are simultaneous.

- **Turn start** (`Game::start_turn`): pairings are published (`Player::next_opponent`); then
  per player Gold (3, +1 a turn up to `gold_refill_cap` 10, plus bonuses), upgrade discount,
  temporary effects expire, the Tavern refreshes (frozen cards stay), trinket offers on turns 6
  and 9, start-of-turn hooks (player-level cards, then minions left to right), scheduled effects,
  hand effects, triples.
- **End turn** (`Game::end_turn`, refused while a choice is pending): end-of-turn hooks run
  `Ctx::end_of_turn_mult` times, choices they open resolve at random, temporary cards leave the
  hand, and the warband is kept in `Player::last_board`. The last seat to end starts the round.
- **Combat round** (`Game::combat_round`): nobody meets an opponent (ghost included) from their
  last two combats unless no other pairing exists; with an odd count one player fights the
  ghost, the last eliminated player's final warband. Each side remembers the warband it fought
  (`Player::scouted`). Players at 0 Health are eliminated, their cards return to the pool, and
  simultaneous eliminations rank by Health + Armor (lower seat first on ties). A hero at 0 Health
  in the recruit phase is eliminated at once (`Game::recruit_deaths`).

## Combat

The first attacker is the side with more minions, then the higher Tavern Tier, then random.
Start of Combat runs in stages: trinkets, Quest Rewards and Quests → Hero Powers → "Start of
Combat" Tavern-spell effects → minions in hand → minions on the board; in each stage the first
attacker's side goes first and deaths resolve after each effect. Then the sides alternate: the
attacker is the leftmost minion with Attack that has not attacked this cycle and attacks once
(twice with Windfury, four times with Mega-Windfury), each time at a random Taunt minion if any,
else a random non-Stealth minion (`combat::pick_target`). An attack (`combat::do_attack`) drops
Stealth, fires Rally and "whenever this attacks", has both minions deal damage at once (Cleave
also hits the defender's neighbours), then runs the held-back damage events and "after this
attacks"; deaths resolve after every attack. The fight ends when a side is empty or nobody can
attack. The winner deals its Tavern Tier plus its survivors' tiers, capped by `damage_caps` (5,
10 from turn 4, 15 from turn 8) while more than `damage_cap_until_alive` (4) players were alive
at turn start. `CombatOutcome` holds winner, uncapped damage, `truncated` and `CombatStats`.

## Shared pool and Tavern

`Pool` counts the copies left of each lobby minion: `pool_copies_by_tier` (15/15/13/11/9/7/5),
Tier 7 included (only a Tier 7 Tavern draws those). `Ctx::draw_pool_minion` draws by copies left
in a tier range; each `Minion` records the copies it holds (`pool_copies`), returned when it is
sold, consumed or eliminated. A random generated minion is drawn by copies and takes one
(`Ctx::random_minion`); a specific card takes a copy if one is left, else it is an extra that
never returns (`Ctx::take_pool_copy`). Tavern spells have `spell_copies_by_tier` (5/7/9/11/9/7)
minus the copies in any Tavern or hand (`Game::spell_copies_left`). A Tavern holds at most
`shop_max_cards` (7): `shop_minion_slots` minions by tier plus `shop_spell_slots` (1) spell.
Frozen and effect-added cards outrank the Refresh's default fill (`Ctx::shop_make_room`). Freeze
works `freeze_presses_per_turn` (10) times a turn; prices go through `Game::slot_price`. Three
copies merge into a golden minion (`Ctx::check_triples`) whose play gives a Triple Reward (a
Discover from one Tavern Tier higher).

## Determinism, save and load

All randomness comes from one seeded xoshiro256** stream per game (`rng::Rng`, seeded through
SplitMix64 and implemented in the crate, so dependency upgrades never change a replay). Combats,
Taverns, Discovers and bots draw from `Game::rng`, so a seed plus an action sequence reproduces a
game exactly (`deterministic_given_seed` in `tests/games.rs`). A copy (`Game::clone`, Python
`Game.copy()`) carries the random state: a rollout from it sees the original's future Taverns
and Discovers unless the copy gets a fresh `Rng` (`Game::rng` is public).

`Game` implements serde: `serde_json` (Python `Game.state_json()` / `Game.from_json()`) is an
exact save that skips only caches (`Game::uidx`, replay frames). `Game::check_loaded` refuses a
state from another card table (`Game::card_table` vs `CardDb::fingerprint`) or an invalid config.
`BatchEnv::save` / `load` do the same for one game and its episode state (`batch::Episode`).

## Interface

- **`actions`**: 245 discrete actions (`N_ACTIONS`) with an exact legal mask: end turn, Refresh,
  Freeze, Upgrade, two Hero Power slots, Dark Gift, Cancel, buy, sell, activate, choose (16
  options), play (hand card × position), magnetize and move; the layout is in the module docs.
  A pending choice allows only `Choose(i)`, plus `Cancel` while targeting a spell, Hero Power or
  Activate (nothing is paid before the target is chosen). Every action `Game::legal_mask` allows
  is accepted by `Game::apply` (test `every_masked_legal_action_applies`).
- **`obs`**: `obs::observe(game, seat)` gives the player-view `Observation`: `floats` (f32
  features: global state, Quests, pending choice, warband, hand, Tavern, choice options,
  opponents' public state and the warbands seen of them) and `cards` (i32 card-embedding
  indices, 0 = empty, else `CardId + 1`). `taverngym.layout()` gives the block sizes. Only what
  the client shows is encoded: of an opponent's warband, what the player saw in its last combat
  against it (`Game::known_board`), never hands or unfought boards.
- **`env`**: `SoloEnv`, one seat (`agent`) against bots in the other seven; reward 0 until the end,
  then `placement_reward` (1st = 1 ... 8th = −1, linear). An illegal action is ignored and costs
  `illegal_penalty` (−0.01). The Gym-style Python wrapper is `taverngym.BattlegroundsEnv`.
- **`batch`**: `BatchEnv` runs many games with any set of controlled seats (`controlled`);
  scripted bots play the rest. Per slot (one controlled seat of one game) `observe` writes
  features, card indices, mask and a `ready` flag, and `step` takes one action and returns a
  `SlotResult` (reward, done, placement, rejected). Finished games reset with seeds derived from
  (environment seed, game, episode); results do not depend on `threads`; `save` / `load`
  restore one game exactly.
- **`bot`**: heuristic bots (`bot::choose_action`, `play_turn`, `run_bot_game`), cheap and
  deterministic given the game's RNG; they make games varied, not strong.

`Game` (Rust and Python) can also drive every seat, for self-play or search.
`RulesConfig::turn_action_caps` (empty = no cap) limits actions per turn. The PyO3 layer releases
the GIL around game work and passes arrays as little-endian bytes that `python/taverngym` wraps
in numpy. Bad seats and invalid or unknown config keys (`RulesConfig::from_json`) raise
`ValueError`, never a Rust panic. `taverngym.build_info()` reports the extension's `source_hash`
and `taverngym.build_is_current()` compares it with the checkout.

## Rules configuration

Every rule value that is not a published server value is a documented `RulesConfig` field
(`crates/taverngym/src/config.rs`). `taverngym.default_config_json()` lists them; pass a JSON
object of changes to `Game`, `SoloEnv` or `BatchEnv`. Card-specific readings are commented next
to their scripts in `content/`; Timewarp rules are in `docs/TIMEWARP.md`. Engine-wide choices:

| Topic | Convention | Where |
| --- | --- | --- |
| Pools | Copies per tier as above; candidates with a non-standard client pool tag are left out | `pool_copies_by_tier`, `spell_copies_by_tier`, `strict_pool_tag`, `excluded_cards` |
| Lobby and heroes | 5 of 10 types, uniform; 2 hero offers per seat, type-tied heroes only with their type | `lobby_races`, `lobby_types`, `hero_choices`, `hero_type_filter`, `hero_bans` |
| Trigger multipliers | "An extra time" adds up per copy; "twice" / "three times" take the maximum | `Ctx::deathrattle_mult`, `battlecry_mult`, `end_of_turn_mult` |
| Stealth-only defenders | Not attackable; when nobody can attack, the fight is a tie | `combat::pick_target` |
| Trinkets | Lesser turn 6, Greater turn 9, 4 options, blocking, paid on pick; per-trinket conditions | `Game::trinket_offer`, `content::trinket_offers` |
| Dark Gifts | Unlock turn 3, cost 3, 3 uses, 3 options; compatibility rules | `dark_gift_*`, `content::gift_fits` |
| Optional systems | Timewarped Tavern off; experimental mode adds a turn-four Quest, Buddies and Timewarp | `timewarp_enabled`, `experimental_mode`, `Game::extra_action` |

## Safety limits and debugging

These limits are not game rules and are reported. A combat that hits `max_combat_attacks` (400),
the death-round limit or `max_effect_depth`, or stalls, ends as a truncated tie counted in
`Game::truncated_combats`. After turn `max_turns` (100; 0 = none) the survivors are ranked by
Health + Armor (`Game::turn_limit_end`). A driver that finds no seat able to progress sets
`Game::stopped_reason` instead of inventing placements. Below the stack floor, `Ctx::guard`
panics with the trail of re-entrant entry points and writes the game to `TAVERNGYM_GUARD_DIR`.

With `RulesConfig::record_log`, `Game::log` holds a text event log and each `CombatRecord` in
`Game::last_combats` carries replay frames. The `debug` module gives a seat's JSON view
(`debug::view`, Python `Game.view(p)`), the card catalog (`taverngym.catalog_json()`) and
`DebugCmd` commands (`debug::run_debug`, Python `Game.debug(json)`) that edit state or run a
`CombatPreview` on copies; debug commands stay in `debug.rs`, out of game logic.

## Invariants, fuzzing and tests

- `invariants::check` covers zone sizes against rules and interface limits, tier / Gold / Health
  ranges, unique entity ids, stat sanity, no dead minion on a board and distinct placements;
  `pool_balance` and `pool_species_violations` check pool conservation between choices.
- `cargo run --release -p taverngym --example fuzz -- [games] [first seed] [trace]` plays random
  legal actions in every seat and checks invariants, pool conservation and snapshot round trips
  (a short version runs in `tests/games.rs`); `--example stress` plays bot games in both content
  modes; `--example play -- [seed]` prints one game's event log.
- `crates/taverngym/tests/` holds `mechanics.rs` (a focused test per mechanic), `persistence.rs`
  (combat never leaks into the persistent warband) and content tests; modules carry unit tests
  (e.g. `batch`: thread independence, exact save/load); pytest (`tests/`) covers the Python side.
- CI runs `cargo fmt --check`, `cargo clippy --release --all-targets -- -D warnings`,
  `cargo test --release`, `pip install -e ".[test]"` and `pytest`.

## Performance conventions

On hot paths, resolve card ids once with `cardid!("BG25_008")` and use `Player::has_trinket_id`
/ `has_power_id` and `Minion::is_card_id`, not the string forms. `emit` checks the registry's
union masks (`any_listens`, ...) before scanning a zone; `Game::log` takes a closure, so logging
is free when off; `draw_pool_minion` walks `UniverseIndex` without allocating. Benchmark with
`--example bench`, comparing callgrind instruction counts rather than wall-clock time.

## Adding a card

1. Read the normal and golden text in `crates/taverngym/data/cards.json` (or `catalog_json()`).
2. Add `("CARD_ID", Script { …, ..Script::EMPTY })` to `scripts()` in the matching
   `content/*.rs` (a new module also goes into `content::all_scripts`); use `me.golden` /
   `me.g()` for golden numbers and `cardid!` for ids a hook compares against.
3. Add a focused test to `crates/taverngym/tests/mechanics.rs` for a new mechanic, and a `shown`
   hook if the text has a number that depends on state.
4. Run `cargo run --release -p taverngym --example content_report > docs/CONTENT.md`; scripted
   cards join the pools automatically in `ContentMode::Implemented`.
